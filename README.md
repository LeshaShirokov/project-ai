# project-ai — дашборд учёта ИТ-проектов

Многостраничное веб-приложение на **чистом HTML, CSS и JavaScript**: без фреймворков, CDN, сборки и сервера. Все данные хранятся в браузере (`localStorage`).

**Демо:** https://leshashirokov.github.io/project-ai/

## Страницы

### Аналитика — `index.html`
- KPI: всего проектов, в работе, завершено, просрочено, общий бюджет, потрачено (% бюджета), средний прогресс, участников в команде (и сколько из них заняты в проектах; ссылка на «Контакты»).
- SVG-графики: проекты по статусам (кольцевая), бюджет и расходы, технологический стек, ближайшие дедлайны (клик открывает проект на странице «Проекты»).

### Проекты — `projects.html`
- Два представления: **таблица** и **канбан** по статусам (перетаскивание карточек или выбор статуса с клавиатуры).
- Поиск, фильтры по статусу, приоритету и технологии; сортировка по дедлайну, приоритету, прогрессу, бюджету, названию.
- **Карточка проекта** (просмотр): статус, приоритет, даты, бюджет, команда, теги, репозиторий, чек-лист задач. Кнопки «Изменить» и «Удалить» (с подтверждением).
- **Форма проекта** (создание/редактирование): название, клиент/владелец, описание, статус, приоритет, стек, команда, начало и дедлайн, бюджет и расходы, прогресс, репозиторий, теги — с проверкой полей.
- **Задачи**: добавление, отметка выполнения, удаление, необязательный срок закрытия; просроченные открытые задачи подсвечены. Режим «считать прогресс по задачам».
- **Команда**: выбор с поиском из контактов с отметкой «Команда работников» плюс участники не из контактов (текстом через запятую).
- Модальные окна помещаются в экран на любой ширине (от 320 px) и высоте: тело прокручивается, шапка и кнопки всегда видны.

### Контакты — `contacts.html`
- Поля: фото, ФИО, телефон, организация, почта, комментарии, отметка «Команда работников».
- Карточки или таблица, поиск, фильтры (все / только команда / внешние, по организации), сортировка по ФИО и организации; карточка контакта со списком его проектов.
- Фото загружается с устройства (JPG, PNG, WebP, GIF, до 5 МБ), обрезается по квадрату и сжимается в браузере до 256 px JPEG; без фото — аватар с инициалами.
- Проверка телефона и почты, российские номера приводятся к виду `+7 (900) 123-45-67`.
- Удаление контакта или снятие отметки «Команда работников» у участника проектов требует подтверждения и убирает его из команд.

### Календарь — `calendar.html`
- Виды **День / Неделя / Месяц** (неделя с понедельника), кнопки «‹ Сегодня ›», выделение сегодняшнего дня.
- Показывает задачи по сроку закрытия, а также дедлайны (⚑) и старты (▶) проектов; цвет — проект, выполненные зачёркнуты, просроченные — красные.
- Клик по элементу — карточка: отметка выполнения, смена срока, ссылка на проект. Кнопка «＋ Задача» добавляет задачу со сроком.
- Фильтры: проект, открытые/выполненные, показ дедлайнов и стартов. Подсказка «N задач без срока» ведёт на «Проекты».
- Клавиатура: стрелки — по дням, PageUp/PageDown — месяц, Home/End — начало/конец недели, Enter — открыть день.

### Общее для всех страниц
- Светлая и тёмная тема (по умолчанию — как в системе), адаптивная вёрстка.
- Синхронизация между вкладками: изменения в одной вкладке сразу видны в других.
- Доступность: навигация с клавиатуры, ARIA-разметка, ловушка и возврат фокуса в модальных окнах, Esc закрывает окно.
- Демо-данные при первом запуске; кнопки «Демо-данные» и «Очистить» на «Проектах» (только проекты) и «Контактах» (только контакты).

### Прямые ссылки
- `projects.html#project=<id>` — карточка проекта, `projects.html#new` — новый проект;
- `contacts.html#contact=<id>` — карточка контакта, `contacts.html#new` — новый контакт;
- `calendar.html#view=month|week|day&date=YYYY-MM-DD` — вид и дата календаря.

## Запуск локально

Откройте `index.html` в браузере или запустите любой статический сервер в корне репозитория:

```bash
python3 -m http.server 8000
# http://localhost:8000/
```

Данные привязаны к адресу (origin): при открытии через `file://` и через `localhost` у вас будут разные наборы данных.

## Хранение данных

Только `localStorage` браузера; на сервер ничего не отправляется.

| Ключ | Что хранит |
|---|---|
| `itpd.projects.v1` | проекты (`{version: 1, projects: [...]}`) |
| `itpd.contacts.v1` | контакты, включая фото |
| `itpd.initialized`, `itpd.contacts.initialized` | демо-данные уже загружались (после «Очистить» не появятся снова) |
| `itpd.theme` | тема |
| `itpd.view`, `itpd.contactsView` | выбранное представление списков |
| `itpd.calendar` | последний вид, дата и фильтры календаря |

- Фото хранится как data URL JPEG (обычно до ~150 тыс. символов, при загрузке/импорте — не больше 400 тыс.). Общая квота `localStorage` — обычно около 5 МБ на сайт; если места не хватает, изменение откатывается и показывается ошибка.
- Если `localStorage` недоступен (например, запрещён в браузере), приложение предупреждает, что данные не сохранятся.

## Экспорт и импорт

- **Проекты → «Экспорт JSON»** — полная резервная копия: `{app, version: 1, exportedAt, projects, contacts}`.
- **Проекты → «Импорт JSON»** — после подтверждения **заменяет** проекты; если в файле есть `contacts`, заменяет и контакты. Принимаются также файлы без `contacts` и просто массив проектов.
- **Контакты → экспорт/импорт JSON** — только контакты (`{..., kind: "contacts", contacts}`); импорт тоже заменяет текущие контакты. Подходит и полная резервная копия.
- **CSV** (разделитель `;`, UTF-8, открывается в Excel, защита от формул) — для проектов (с числом задач, просроченными задачами и ближайшим сроком) и для контактов (без фото). Импорта CSV нет.

Формат проекта: `id, name, client, description, status` (`idea | planning | active | paused | done | cancelled`), `priority` (`low | medium | high | critical`), `stack, tags, team` (массивы строк), `teamIds` (ID контактов), `start, deadline` (`YYYY-MM-DD`), `budget, spent, progress, autoProgress, repo, tasks, createdAt, updatedAt`. Задача: `{id, text, done, due}`, где `due` — `YYYY-MM-DD` или пустая строка.

Формат контакта: `id, name, phone, org, email, comment, isTeam, photo, createdAt, updatedAt`.

При импорте данные проверяются и нормализуются: неизвестный статус/приоритет заменяется значением по умолчанию, некорректные даты и ссылки очищаются, длинные строки обрезаются. Старые проекты, где команда записана текстом, связываются с контактами автоматически, если имя однозначно совпадает с контактом из команды работников.

## Ограничения

- Данные живут в одном браузере на одном устройстве: нет сервера, учётных записей и совместной работы; очистка данных сайта удаляет всё — делайте «Экспорт JSON».
- Объём ограничен квотой `localStorage` (~5 МБ), в основном его занимают фото.
- Лимиты: название — 120 символов, описание — 2000, задача — 200; до 200 задач в проекте, до 50 участников-контактов, до 5000 записей за один импорт.
- Импорт всегда заменяет данные (без слияния); импорта CSV нет.
- Одновременная правка одной записи в двух вкладках: побеждает последнее сохранение.

## Структура репозитория

```
index.html            страница «Аналитика»
projects.html         страница «Проекты»

.nojekyll             отключает обработку Jekyll на GitHub Pages

js/utils.js           DOM-хелперы, даты, форматирование, CSV (все)
js/store.js           проекты: модель, валидация, хранение, импорт/экспорт (все)
js/contacts-store.js  контакты: модель, валидация, хранение, импорт/экспорт (все)
js/ui.js              модальные окна, уведомления, бейджи, аватары (все)

js/shell.js           тема, меню, синхронизация вкладок (все)
js/charts.js          SVG-графики (аналитика)
js/dashboard.js       KPI и запуск страницы «Аналитика»
js/views.js           таблица, канбан, карточка проекта (проекты)
js/projects.js        фильтры, форма, выбор команды, импорт/экспорт (проекты)
js/photo.js           проверка и сжатие фото (контакты)
js/contacts.js        список, фильтры, форма и карточка контакта (контакты)
js/cal-dates.js       даты календаря: недели, сетка месяца, заголовки (календарь)
js/calendar.js        виды день/неделя/месяц, фильтры, карточка и форма задачи (календарь)
```

## Публикация на GitHub Pages

Сайт публикуется из ветки `main`, папка `/` (Settings → Pages → Deploy from a branch). Сборка не нужна: после `git push` в `main` GitHub Pages обновляет сайт обычно за 1–2 минуты. Все пути относительные, поэтому сайт работает и в подпапке `/project-ai/`. Файл `.nojekyll` оставляет файлы как есть, без обработки Jekyll.
